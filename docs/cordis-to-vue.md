# cordis → Vue: the mapping

> Phase-1 deliverable, 2026-08-20. Port of the PoC-era design doc (`conversations/260819-vue-harness-poc/设计文档-cordis核心能力的Vue表达.md`) onto the modular codebase — module paths instead of line numbers, plus the concepts added after the 3-model ensemble review (declarative contributions, name-keyed collector, per-request snapshot, token-guarded cleanup).
>
> The question this answers: **for every core capability cordis gives deepseek-harness, which Vue built-in carries it here.** Principle: anything expressible on a Vue platform primitive is not hand-written; the only fully hand-rolled mechanism is the event bus (Vue has no equivalent).

## The mapping table

| cordis capability | cordis semantics | Vue expression | where |
|---|---|---|---|
| Fiber plugin instance | `ctx.plugin()` creates a runtime instance; parents/children form a tree | **component instance**: a plugin is a component options object pushed into the reactive `plugins` array; v-for render = mount | `src/kernel/host.js` |
| Fiber state machine (PENDING/ACTIVE/FAILED + retry) | waits while injects missing, activates, fails | **compile-probe + PluginHost error card**: compile failure never mounts (≈PENDING); runtime errors hit the error boundary → failed card + retry (version++ remount) | `src/kernel/compile.js`, `src/kernel/host.js` |
| registrations are effects | every outward effect goes through `ctx.effect`, reclaimed in reverse on dispose | **component effect scope**: watchers stop on unmount automatically; `onUnmounted` wiring is built into `provideService` / collector `add` / `useBusOn` | `src/kernel/services.js`, `src/kernel/collector.js`, `src/kernel/bus.js` |
| scope tree + cascading disposal | Fiber tree, children die with parent | **component tree**: unmount = splice from `plugins` = full automatic reclamation of watchers/DOM/children | `src/kernel/host.js` |
| service DI container | `ctx.provide/inject` over a Context prototype chain | **single injection point + reactive registry**: `shallowReactive(Map<name, shallowRef>)`; siblings reach each other through the registry, not the tree | `src/kernel/services.js` |
| declarative inject + readiness-driven activation | plugin stays PENDING until services appear | **`useService(name)` returns a computed**: appears/replaced/removed all propagate automatically — more automatic than cordis's manual notify/epoch | `src/kernel/services.js` |
| config (schema check + update restart) | StandardSchema validation, update = restart | **props declarations** (type/required/default/validator) + `:key` containing `version`; `version++` forces a clean remount | `src/kernel/host.js`, frame template in `src/entries/standalone/main.js` |
| error isolation | a crashing plugin must not take down the runtime | **`onErrorCaptured` boundary** per PluginHost → failed card + retry | `src/kernel/host.js` |
| event bus emit/on + waterfall | five dispatch modes; waterfall middleware can short-circuit (veto) | **hand-rolled bus (~40 lines)**: emit/on + waterfall (skip `next()` = veto), double-`next()` detection, per-listener owner attribution. The one capability with no Vue counterpart | `src/kernel/bus.js` |
| **tool / prompt registries** | `ctx.tools.register(defineTool(…))`, `ctx.systemPrompt.section(…)` | **rendered contributions**: `<AgentTool>` / `<PromptSection>` — mount = register, unmount = dispose, the template is the plugin's manifest; `useTool` / `usePromptSection` are the equal-citizen composable face over the same name-keyed collector | `src/kernel/collector.js`, `src/plugins/tools.js`, `src/plugins/prompt.js` |
| ui-slots / session projections | declaration = render authorization; disposer collapses subtree | **no registry at all**: a plugin's render output IS its panel; placement = native `<Teleport>` to target *elements* handed out by the layout service (never `#id` selectors — Phase-2 host pages own their ids) | `src/plugins/ui/layout.js`, frame in `src/entries/standalone/main.js` |
| HMR (cordis-hmr) | watch file → clear cache → remount new code under old config → roll back on failure | **the reactive fs cache IS the change signal** (no chokidar layer at all) + compile-probe + def swap & version++; failure = old version keeps running, `hmrError` badge | `src/plugins/manager.js`, `src/plugins/fs.js` |
| runtime plugin creation (Creator) | agent writes source → runtime compile & mount → persistence & restore | `create_plugin` meta-tool → compile-probe → OPFS write → mount; boot scan restores (with a `formatVersion` gate so a dialect bump can't brick restore) | `src/plugins/tools/create-plugin.js`, `src/plugins/manager.js` |
| agent-readable UI state | (store bridge: React UI state mirrored into a framework-agnostic store the harness can read) | **`expose()` + vnode ref**: a plugin opts in with `ctx.expose({...})` — Vue's own primitive for a curated public surface; PluginHost captures the exposed proxy (token-guarded map), the `read_state` tool + a request-time prompt index are the read face. Pull-based: state costs tokens only when the model asks | `src/kernel/host.js`, `src/plugins/state.js`, `src/plugins/tools/read-state.js` |
| async teardown (awaitable dispose) | disposers may be async, awaited LIFO | **not done** (deliberate): unmount is synchronous; async cleanup is fire-and-forget | — |

## What the rewrite added beyond the PoC's mapping

1. **Contributions are rendered, not registered** (the step past porting the registry idiom). What it buys: `v-if` on a contribution is a live feature toggle (setup-only composables can't do this — setup runs once), `v-for` stamps out N tools from config, DevTools shows contributions as child instances, and the agent-facing plugin recipe lost all disposer discipline. Model-facing prose travels in **props, never slot text** — vnode-walking cannot extract `{{ interpolation }}` (ensemble-verified).
2. **Name-keyed collector, fail-loud duplicates** (`src/kernel/collector.js`). Instance-keying hides duplicates → two same-name tools → OpenAI-gateway 400 (the PoC burned a day on this). Policy: same plugin re-adding = HMR remount = replace (robust to either mount/unmount order because removal is token-guarded); a *different* plugin colliding = throw, surfaced in its PluginHost card.
3. **Per-request snapshot** (`src/plugins/loop.js` + `tools.snapshot()`). At `llm/request` the loop freezes the assembled prompt and the tool dispatch table; execution dispatches against what the model actually saw. Without this, HMR or `v-if` removing a tool mid-turn races the model's selection of it — a latent PoC bug.
4. **Token-guarded cleanup** (`services.js`, `collector.js`). Name-based delete-on-unmount can delete a *replacement* that mounted before the old instance unmounted. Guard: only delete if the slot still holds your own token.
5. **The system prompt is assembled, not hardcoded**: a computed over collected `<PromptSection>`s (order-sorted), so capabilities carry their own instructions and unmounting one removes its prose from the next request.
6. **One namespaced Vue** (`globalThis.__harness.Vue`, never `window.Vue`): dynamic plugins import nothing; there must be exactly one Vue namespace across the shipped/self-modified boundary or provide/inject and reactivity silently break. `window.Vue` is reserved for Phase-2 host pages that may own it.
7. **Context compaction as a plugin** (`src/plugins/compaction.js`, added 2026-08-20). The loop stays policy-free: it fires `loop/turn-start` (before each request is assembled) and `loop/llm-error` (after a failed stream) and owns only a 500-turn runaway failsafe. The compaction plugin holds the policy — pi-coding-agent's recipe (usage + chars/4 estimate, reserve 16384, keep recent 20000, one tool-less summarizer call, `{ role: 'summary' }` checkpoint splice, overflow → compact-and-retry-once via pi-ai's `isContextOverflow`) — and could be unmounted or replaced at runtime like any other plugin.

## Architecture correspondence

deepseek-harness's browser side is three layers: React UI + embedded cordis loader + framework-agnostic store bridge. Here the three collapse into one — **the component system is simultaneously the render layer, the plugin lifecycle layer, and the state synchronization layer.** The kernel (`src/kernel/`, ~230 lines with comments) is the whole translation; everything else, panels included, is a plugin riding it.
